# 실시간 중량 전송

Gateway의 중량 WebSocket 하나로 각 계량대의 수신 이벤트를 개별 전송한다. 현재 서버의 `docs/live-weights.md`와 `docs/live-weights-client-handoff.md`를 기준으로 중량·시리얼 상태·Gateway 생존 확인을 구분한다. 서버는 세 메시지 유형을 지원하며, 기존 전체 배열 입력 `weights.updated`와 이전 클라이언트의 `weights.heartbeat`는 지원하지 않는다.

## 연결과 메시지

경로는 `/ws/devices/gateways/<gateway_id>/weights/`, 인증 헤더는 `Authorization: Gateway <token>`이다. HTTPS 서버에는 `wss://`를 사용한다. 장비 검색·설정용 제어 연결과 별도로 유지하며 화면을 열지 않아도 전송한다.

공용 송신 작업 하나가 세 메시지 유형의 `sequence`를 부여한다. 새 WebSocket에서 1부터 시작하고 실제 전송마다 증가한다. UTF-8 JSON 텍스트를 사용한다.

### 시리얼 상태

초기 준비 상태와 시리얼 상태 변경은 `station.status`로 보낸다. `connection_status`는 `waiting`, `connected`, `disconnected`, `error` 중 하나다. 시리얼 연결에 성공하면 첫 중량 전에도 `connected`를 보낸다.

```json
{
  "type": "station.status",
  "sequence": 1,
  "payload": {"station_id": 3, "connection_status": "connected"}
}
```

상태 변경은 샘플을 새로 측정한 일이 아니다. 서버는 다음 실제 샘플을 기다리는 상태로 전환하며, 시리얼이 복구되어도 이전 중량을 다시 표시하지 않는다. 클라이언트도 상태 변경보다 앞선 대기 샘플을 폐기한다.

### 실제 중량 수신

유효한 장비 응답마다 `weight.updated`를 보낸다. 같은 숫자를 새로 측정한 경우에도 `sample_seq`를 증가시킨다. 미수신 상태를 중량 `0`이나 샘플 순번 `0`으로 보내지 않는다.

```json
{
  "type": "weight.updated",
  "sequence": 2,
  "payload": {
    "station_id": 3,
    "weight": "1234.50",
    "unit": "kg",
    "weight_status": "ST",
    "weight_type": "NT",
    "sampled_at": "2026-10-13T09:00:00+09:00",
    "sample_age_ms": 25,
    "sample_seq": 1,
    "connection_status": "connected"
  }
}
```

- `sampled_at`은 시간대가 있는 실제 취득 시각이며 `sample_age_ms`는 송신 시점까지 단조 시계로 계산한 경과 밀리초다. 두 필드 모두 필수이고 `null`을 보내지 않는다.
- `sample_seq`는 1 이상이며 같은 WebSocket에서 계량대별로 엄격하게 증가한다. 시리얼 재연결·worker 교체 시에도 증가를 이어간다. 상태 전송으로 초기화하지 않는다.
- `weight`는 소수·음수·0을 포함하는 숫자 문자열이고 최대 32자, 절댓값 1,000,000,000 이하다. `ST`·`US`는 숫자가 필수이며 `OL`·`00`만 `null`을 허용한다. `connection_status`는 `connected`만 보낸다.
- 장비의 숫자 변환 실패나 유효하지 않은 값은 오류 상태로 보고한다. 실제 샘플의 시각·순번을 만들어 내지 않으며 업무용 장비 응답 처리와 구분한다.
- `unit`은 비어 있지 않은 최대 8자 문자열이다. 장비 단위를 그대로 전달하며 환산하지 않는다. `weight_type`은 `NT`, `GS`, `TR`, `00` 중 하나다.

### Gateway 생존 확인

중량·상태를 전송하지 않은 동안에는 1초 간격으로 다음 메시지를 보낸다. 중량이나 상태가 계속 전송되면 별도 heartbeat를 생략한다.

```json
{"type": "gateway.heartbeat", "sequence": 3}
```

Heartbeat는 개별 계량대의 중량·상태·취득 시각·샘플 순번을 바꾸지 않는다. 서버는 마지막 정상 메시지부터 6초 이상 지나면 Gateway 연결을 확인할 수 없는 것으로 판단한다. WebSocket ping/pong은 이 메시지를 대체하지 않는다.

## 지연과 재연결

장비 thread는 계량대별 최신 상태를 보관하고 송신 작업을 깨운다. 네트워크 전송 완료를 기다리지 않는다. 송신이 밀리거나 끊기면 계량대별 최신 상태와 현재 시리얼 연결에서 유효한 최신 샘플만 보존한다. 과거 샘플·상태의 대기열은 누적하지 않는다. 전송 중인 메시지는 취소하여 바꿀 수 없지만 다음 전송에서는 갱신된 상태를 사용한다.

단절·오류·대기 또는 시리얼 재접속이 발생하면 이전 샘플을 무효화한다. 복구된 `connected` 상태를 보낸 뒤에는 새 실제 수신을 기다린다. 이미 같은 소켓에서 보낸 샘플을 heartbeat 대신 반복하지 않는다.

WebSocket 재연결 시에는 각 계량대의 현재 상태를 먼저 보내고, 유효한 최신 샘플이 있는 계량대만 이어서 중량을 보낸다. 원래 `sampled_at`과 `sample_seq`를 유지하고 경과 나이만 다시 계산한다. 새 연결에서는 서버의 샘플 순번 비교가 다시 시작하므로 이 최신 샘플을 한 번 전송할 수 있다.

계량대 삭제·worker 교체 시 이전 worker의 중지와 callback 완료를 기다린 뒤 보관소에서 제거한다. 새 worker는 이전 worker가 종료된 후 시작한다. 서버 소속 목록에서 제외된 계량대는 더 이상 송신하지 않는다.

## 연결 거부와 운영 대응

| 상황 | 클라이언트 동작과 확인할 내용 |
| --- | --- |
| 네트워크 장애·정상 연결 종료·`1012`·`1013` | 지연을 늘려 재연결하고 현재 상태와 유효한 최신 샘플부터 전송한다. |
| `4403` 비소속 계량대 | 서버의 최신 계량대 설정을 다시 동기화한다. 동기화 성공 전에는 중량 연결을 다시 열지 않는다. |
| `4409` 소유권·순번 위반 | 실시간 발행을 중단한다. 다른 발행 프로그램이 연결을 인수했을 수 있어 자동으로 소유권을 되찾지 않는다. 중복 실행·순번 처리를 확인한다. |
| `4400`·`1009`·`4429` | 잘못된 입력·크기·과도한 송신을 확인하도록 실시간 발행을 중단한다. |
| `4401` 또는 HTTP 협상 `401`·`403` | Gateway ID·토큰을 확인하도록 실시간 발행을 중단한다. |

발행 중단은 해당 클라이언트 프로세스에서 유지된다. 원인을 해결한 뒤 클라이언트를 정상 재시작해야 한다. 제어 WebSocket이 다시 연결되었다는 이유만으로 발행을 재개하지 않는다. 중량 발행 오류는 기존 계량·전표 출력·완료 기록의 로컬 저장·HTTP 업로드를 중단하지 않는다.

서버의 메시지 크기 상한은 16,384바이트, 세 유형 합계의 안전 상한은 최근 1초에 1,000개다. 이 수치는 권장 송신 주기나 보장 처리량이 아니다. 서버는 메시지별 성공 ACK를 보내지 않으므로 실시간 전송 성공을 계량 완료 기록 저장 성공으로 해석하지 않는다.

## 검증 범위

자동 테스트는 초기 상태, 동일 중량의 새 수신, 다중 계량대, 송신 지연과 샘플 폐기, 상태·샘플 순서, heartbeat, 재연결, 샘플 순번 유지, 서버 종료 코드에 따른 대응을 확인한다. 실제 서버 검증 결과와 실행 조건은 작업 기록에 보관하며, 테스트용 시리얼 응답과 실제 현장 장비·WSS·Windows 인수 검증을 구분한다.
