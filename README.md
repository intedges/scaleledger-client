# ScaleLedger Client

ScaleLedger Client는 수산물 계량 현장의 Windows PC에서 SUWOL-1000 계량 장비와 통신하는 프로그램입니다. RFID 카드를 확인하고 중량을 읽어 계량 전표를 출력하며, 계량 기록을 ScaleLedger 관리 프로그램에 전달합니다. 별도 조작 화면 없이 실행되고, 기준정보와 장비 등록은 관리 프로그램의 브라우저 화면에서 처리합니다.

이 문서에서 운영자의 일상 사용·장애 대응과 설치 담당자의 설치·설정 절차를 함께 안내합니다. 현재는 개발 중이며, 실제 Windows PC와 장비에서 인수 검증을 마친 뒤 운영에 사용해야 합니다.

## 사용 구성과 업무 흐름

첫 운영은 **인터넷이 연결되지 않은 Windows PC 한 대**에서 다음 프로그램을 함께 실행하는 구성을 목표로 합니다. 설치 담당자가 Python 환경과 장비 드라이버를 준비하며, 클라이언트는 PC 부팅 시 로그인 전부터 자동으로 실행됩니다. 관리 프로그램의 부팅 자동 실행은 해당 서버의 배포 절차로 별도 구성합니다.

| 구성 | 역할 |
| --- | --- |
| ScaleLedger 관리 프로그램 | 생산자·품목·카드 배정, 장비 설정과 계량 기록을 관리합니다. |
| ScaleLedger Client | 연결된 계량 장비에서 RFID와 중량을 읽고 계량 전표를 출력합니다. |
| 브라우저 | 운영자가 기준정보를 등록하고 계량 기록을 확인합니다. |
| SUWOL-1000과 프린터 | 계량·카드 인식·전광판·음성 안내·종이 전표 출력을 담당합니다. |

관리 화면에서 **Gateway**는 장비가 연결된 PC, **Station**은 그 PC에 연결된 계량대를 뜻합니다.

1. 업무 시작 전 PC의 날짜와 시간, 장비 전원·연결, 프린터 용지를 확인합니다.
2. 관리 프로그램과 클라이언트의 실행 상태, 사용할 생산자·품목·카드 배정을 확인합니다.
3. 등록된 카드를 사용해 계량하고 장비 안내와 출력된 전표를 확인합니다.
4. 전표와 관리 화면의 계량대·생산자·품목·중량·측정 시각이 일치하는지 확인합니다.
5. 업무를 마칠 때는 새 계량 입력을 멈추고 처리하던 계량 기록을 확인합니다. 프로그램을 따로 중단하거나 설정을 바꿀 때는 아래 정상 종료 바로가기를 사용합니다.

전표에는 측정 시각, 전표번호, PC·계량대 이름, 생산자·품목, 카드번호와 중량이 표시됩니다. 현재 전표 양식은 고정되어 있습니다.

생산자가 지정된 활성 카드는 품목을 지정하지 않아도 계량할 수 있습니다. 이 경우 전표의 품목명은 빈칸으로 출력되며, 관리 프로그램에서 계량 기록에 품목을 나중에 지정해도 카드와 이미 출력한 전표는 바뀌지 않습니다.

### 차량 진입과 카드 접수 안내

차량 판정 기준은 **진입 50kg 초과 1초 이상, 빈 상태·이탈 50kg 이하 1초 이상**입니다. 프로그램 시작·재시작 후에도 먼저 50kg 이하가 1초 이상 유지되는지 확인합니다. 차량이 올라와 50kg 초과가 1초 유지되면 녹색등 출력만 활성화하고 “카드를 대어주십시오”라고 안내합니다. 별도의 최소 관측 횟수 조건은 없습니다. 50kg 이하는 진입으로 인정하지 않으며, 중간에 조건이 깨지거나 통신 실패·잘못된 중량이 발생하면 확인 시간을 다시 셉니다. 장비의 안정 신호는 필수 조건이 아닙니다. 1초 기준에서는 차량이 다 올라오기 전에도 카드를 받을 수 있으므로, 설치 담당자는 차량이 계량대에 완전히 올라와야 카드 리더에 손이 닿는지 확인합니다.

유효 중량 갱신이 **5초 이상 없음을 확인하면** 관측 이력을 초기화하고 진입·빈 상태·이탈 확인 시간을 다시 셉니다. 관측 제한은 통신 타임아웃과 별도로 고정된 5초입니다. 작업 루프와 새 중량 반영 시점에 검사하며, 이미 계량한 차량의 재접수 잠금과 저장 중이거나 저장된 기록은 보존합니다. 진입·이탈 확인은 새 중량 응답이 도착했을 때만 진행하므로 통신이 느리면 접수 준비도 늦어질 수 있습니다. 카드 접수와 중량 확정에는 **수신 후 2초 이내의 중량**만 사용합니다. 이미 계량한 차량은 빈 계량대가 다시 확인되어야 다음 차량을 받습니다.

카드를 대면 카드 확인, 그 순간의 중량 확정, PC 로컬 DB 저장 확인을 거쳐 바로 전표를 출력합니다. 음성 안내가 끝나기를 기다리지 않으며, 정상적인 통신 환경에서는 카드를 댄 뒤 전표 출력 명령 전송을 마치기까지 1초 안팎이 걸립니다. 실제 인쇄 시간은 프린터 동작에 따라 더해집니다.

| 상황 | 음성 안내 |
| --- | --- |
| 녹색등이 켜진 뒤 카드를 대기 전 | “카드를 대어주십시오”를 5초마다 반복합니다. 카드를 대거나 차량이 50kg 이하로 내려가면 멈춥니다. |
| 전표 출력 후 차량이 계량대 위에 있는 동안 | “계량이 끝났습니다”를 5초마다 반복합니다. 출력 전에 차량이 내려갔어도 한 번은 안내합니다. 중량을 읽지 못하거나 통신이 끊기면 계량한 차량이 그대로 있는지 알 수 없으므로 반복을 멈춥니다. |
| 계량한 차량이 50kg 이하로 내려감 | “이용해주셔서 감사합니다”를 한 번 안내합니다. 내려간 것을 중량으로 확인한 경우에만 안내합니다. |
| 미등록·비활성 카드 | 적색등과 “등록되지 않은 카드입니다”로 알리고, 안내가 끝나면 녹색등으로 돌아가 다른 카드를 받습니다. 다른 안내가 재생 중이면 그 뒤에 나오며, 적색등은 최대 5초입니다. |
| 로컬 저장 실패 | 적색등과 “관리자에게 확인하십시오”를 30초마다 안내합니다. |
| 녹색등 전 태그, 계량 후 재태그 | 음성 없이 무시합니다. 녹색등이 켜진 뒤 다시 대야 합니다. |

반복 주기 5초는 앞 안내가 시작된 때부터 셉니다. 시험 장비에서 잰 재생 시간은 “카드를 대어주십시오” 약 1.9초, “계량이 끝났습니다” 약 1.3초, “이용해주셔서 감사합니다” 약 2.7초입니다. 장비는 재생 중인 방송을 끊을 수 없으므로 다른 안내는 앞 방송이 끝난 뒤 이어서 나옵니다. 방송이 재생 중이어도 카드 접수와 전표 출력은 바로 진행합니다.

| 등 표시 | 의미와 운영 방법 |
| --- | --- |
| 녹색 출력만 활성 | 카드 접수 가능. 계량카드를 한 번 대면 됩니다. |
| 녹색·적색 출력 모두 활성 | 카드 확인·계량 저장·출력 또는 영점 조정 처리 중. 추가 태그는 받지 않습니다. |
| 적색 출력만 활성 | 미등록 카드, 저장 실패, 유효하지 않은 중량 등 문제가 있습니다. 음성과 로그를 확인합니다. 적색 출력만 활성인 동안에는 카드를 받지 않습니다. |
| 두 등 꺼짐 | 초기 빈 계량대 확인·차량 진입 대기 또는 출력 후 차량 이탈 대기입니다. 카드 접수가 가능한 상태가 아닙니다. |

녹색등은 완료 표시로 사용하지 않습니다. 전표 출력 명령을 보내면 처리 중 표시를 해제합니다. 통신이 끊기면 마지막 등 표시가 장비에 남을 수 있으므로, 등만으로 연결 상태를 판단하지 않습니다. 실제 점등 방식은 장비에서 확인해야 합니다.

음성 명령을 보낸 뒤 15초 안에 재생 종료를 확인하지 못하면 경고 로그를 남깁니다. 음성 오류만으로 카드를 취소하거나 적색등을 켜지 않으며 계량·저장·전표 출력은 계속합니다. 재생 여부가 불확실하면 해당 방송의 재생과 종료를 확인할 때까지 새 안내를 보내지 않고, 지난 안내를 뒤늦게 몰아서 재생하지 않습니다. 시작 상태를 끝내 확인하지 못하면 안내 생략이 지속될 수 있고 시리얼 재연결만으로 해제하지 않습니다. 이때 완료 음성 유무만으로 저장 여부를 판단하지 말고 전표·기록을 확인한 뒤 담당자에게 알립니다.

차량 한 번 진입에 계량은 한 번만 허용합니다. 완료 후 같은 카드나 다른 카드를 다시 대어도 추가 기록·전표를 만들지 않습니다. 50kg 이하가 1초 이상 유지되는지 확인한 뒤 다음 차량의 진입을 받으므로, 빈 상태가 확인되기 전에 다음 차량이 올라오면 그 차량은 한 번 내렸다가 다시 올라와야 합니다. 저장·출력 중에도 차량 이탈을 관측하지만 진행 중인 계량 처리가 끝나기 전에는 다음 카드를 받지 않습니다. 저장이 늦어져 앞 차량의 이탈이 확정된 뒤에 출력하면 그 차량의 완료·감사 안내는 생략합니다. 빈 계량대나 녹색등 전에 태그한 카드는 이후 차량에 자동 적용하지 않습니다.

처리 중·완료 후 재태그로 저장을 다시 시작하지 않습니다. 차량 상태는 메모리에만 유지하므로, **차량이 올라간 상태에서 프로그램을 재시작하면 차량을 한 번 내린 뒤 다시 진입해야 합니다.** 시리얼 재연결은 이미 계량한 차량의 잠금을 해제하지 않습니다.

진입·빈 상태·이탈 각각 1초와 50kg 기준, 관측 미갱신 5초, 안내 주기는 현재 프로그램 기본값이며 관리 화면이나 TOML에서 변경하는 기능은 없습니다. 차량 감지는 장비가 전달하는 kg 중량을 사용합니다. 용기·영점 조작으로 차량이 남아 있는데도 값이 0에 가까워지는 운용은 이탈로 판단될 수 있으므로, 설치 담당자는 차량 존재를 반영하는 중량 종류와 장비 운용 방식을 확인해야 합니다.

**계량 기록을 PC의 로컬 DB에 저장한 것을 확인한 뒤 전표 출력과 완료 안내를 진행합니다.** 관리 프로그램으로의 전송 완료는 기다리지 않으므로, 서버 기록은 별도로 확인해야 합니다. 서버 기록이 없거나 내용이 다르면 출력물을 보관하고 발생 시각과 계량대를 담당자에게 전달합니다. 완료 음성은 프린터의 실제 출력 성공을 보장하지 않습니다.

로컬 저장이 지연되거나 실패하면 출력과 완료 안내를 보류하고 해당 계량대에서 새 카드를 처리하지 않습니다. 대기가 길어져도 기존 저장 결과를 계속 확인하며, 실패 결과를 받으면 같은 전표번호·중량·측정 시각으로 5초 간격을 두고 재시도합니다. 저장이 확인되면 기존 계량의 출력과 안내를 이어갑니다. 전표와 완료 안내가 모두 나오지 않으면 계량물을 유지하고 담당자에게 알립니다. 카드 재태그나 재시작 전에 저장 여부를 확인해야 중복 계량을 피할 수 있습니다.

관리 프로그램의 **실시간 계량** 화면에서는 모든 계량대의 현재 중량과 수신 상태를 함께 확인할 수 있습니다. 장비 등록과 설정 동기화가 완료되면 클라이언트가 화면을 열어 두지 않아도 장비 응답마다 중량과 주요 상태를 계속 전달합니다. 값이 같아도 새 응답이면 해당 계량대의 정보를 개별 전송하며, 다른 계량대의 응답을 기다리지 않습니다. 실제 장비 응답이나 전표 출력에 따라 표시가 늦어질 수 있습니다.

실시간 화면의 값은 계량 기록 저장이나 전표 출력 완료를 뜻하지 않습니다. 수신이 지연되거나 끊겼을 때는 연결·수신 상태 문구를 확인합니다. 전송이 밀리거나 연결이 끊기면 각 계량대의 최신 상태만 유지하며, 연결이 복구되면 최신 상태부터 표시합니다. 네트워크 전송은 장비 수신과 분리되어 있고, 확정된 계량 기록의 보관·재전송은 기존 방식으로 계속 동작합니다.

이 버전은 중량과 장비 상태를 하나의 `station.telemetry`로 전달하는 서버와 함께 설치해야 합니다. 기존 메시지만 받는 서버에서는 실시간 전송이 거부됩니다. 계량대가 처음 연결되거나 통신 오류에서 복구되면 새 응답을 받을 때까지 모든 관측을 확인 불가로 취급합니다. 중량만 읽지 못한 경우에도 같은 응답의 다른 장비 상태는 전달합니다. 설치 담당자는 새 메시지를 지원하는 서버를 먼저 반영한 뒤 이 버전의 클라이언트를 적용합니다.

### 웹에서 영점 조정 요청

계량대를 비운 뒤 관리 프로그램의 실시간 계량 카드에서 **영점 조정**을 누릅니다. 확인창의 장비 PC와 계량대가 맞는지 확인하고 **영점 조정 요청**을 누르면 해당 계량대에만 요청합니다. 이 기능을 지원하는 서버와 클라이언트가 연결되어 있어야 합니다.

`영점 조정을 요청했습니다. 현재 중량을 확인하세요.`라는 표시는 요청 전달 안내이며 장비의 수신이나 조정 완료를 보장하지 않습니다. 조정 뒤 실제 중량을 확인하세요. 연결이 끊긴 동안의 요청을 보관하거나 재접속 뒤 자동 실행하지 않으며, 응답이 없을 때도 자동 재요청하지 않습니다.

클라이언트는 연결 상태와 최신 안정 중량을 확인한 뒤 영점을 실행합니다. 저장 요청 전의 진행 중 계량은 취소하고, 전표 출력 후 차량 이탈 대기도 초기화합니다. 취소된 카드는 재사용하지 않으므로 조정 후 빈 계량대와 다음 차량의 진입이 확인되면 다시 태그합니다. 저장·출력 중이거나 통신·중량 확인이 안 되는 경우에는 요청을 거절하고 현재 처리를 보존합니다.

영점 실행 시 “찌잉” 경고음을 한 번 요청합니다. 다른 음성이 재생 중이어도 조정은 즉시 진행하며, 경고음만 시작 후 5초 안에 스피커가 비는 때로 미룹니다. 시간이 지나거나 새 카드가 접수되면 지연된 경고음은 생략합니다. 경고음은 조정 성공을 뜻하지 않습니다. 조정이 되지 않으면 중량과 연결 상태를 확인하고 담당자에게 해당 시각의 `biz.active.zero.*`·`hw.zero.*` 로그를 전달합니다.

## 시작·상태 확인·종료

### 시작

설치를 마친 PC는 켤 때마다 로그인 전부터 클라이언트를 실행합니다. 설치 직후 첫 실행이나 정상 종료 후 다시 시작할 때는 설치 때 정한 Windows 운영 계정으로 로그인하여 **바탕화면의 `ScaleLedger Client 시작` 바로가기**를 누릅니다. 별도 창은 열리지 않습니다.

설치 스크립트가 만든 시작 바로가기는 자동 실행과 같은 예약 작업을 시작합니다. 수동으로 만들 때는 아래 설치 절차에 따라 프로그램을 직접 실행하는 바로가기도 사용할 수 있습니다. 어느 방식이든 이미 실행 중이면 추가로 실행하지 않습니다. 프로그램이 종료된 뒤에는 바로가기나 다음 PC 부팅으로 다시 시작합니다. 작업 스케줄러의 실패 재시도 설정만으로 실행 중인 프로그램의 비정상 종료 후 자동 복구를 보장할 수 없으므로, 중단을 발견하면 로그와 작업 상태를 확인한 뒤 다시 시작합니다.

PC가 절전·최대 절전 상태이면 계량할 수 없습니다. 운영 시간에 절전하지 않도록 설치 담당자와 전원 설정을 확인합니다.

### 상태 확인

Windows 시작 메뉴에서 **작업 스케줄러**를 열고 **작업 스케줄러 라이브러리**의 `ScaleLedger Client` 작업을 확인합니다.

| 상태 | 의미와 확인할 내용 |
| --- | --- |
| 실행 중(Running) | 프로그램이 실행 중입니다. 장비 연결과 실제 계량 성공은 전표·관리 화면·로그로 확인합니다. |
| 준비(Ready) | 작업은 등록돼 있지만 현재 실행 중이지 않습니다. 시작 바로가기를 누른 뒤 다시 확인합니다. |
| 작업이 없거나 시작 실패 | 설치 담당자에게 작업 등록·실행 계정·암호·폴더 접근 권한 확인을 요청합니다. |

위 상태는 예약 작업으로 시작한 경우에 해당합니다. 프로그램을 직접 실행하는 바로가기를 사용하면 예약 작업은 준비 상태여도 프로그램이 실행 중일 수 있습니다. 이때는 작업 관리자의 명령줄에서 해당 설치 폴더의 `main.py`를 실행하는 `pythonw.exe`와 최근 로그를 함께 확인합니다.

처음 설치한 PC는 실행하면 관리 프로그램에 승인을 기다리는 장비 PC로 표시됩니다. 관리자가 승인해야 서버에서 계량대·카드 설정을 받아 계량을 시작합니다. 작업이 실행 중이라는 표시만으로 첫 설정이 완료됐다고 판단하지 않습니다. 장비 PC 승인과 장비 연결 인증을 지원하는 서버와 함께 설치해야 하며, 이전 버전 서버에는 등록할 수 없습니다.

관리 화면의 마지막 통신 시각은 서버가 확인을 요청하고 클라이언트가 응답했을 때 갱신됩니다. 이 버전은 제어 연결로 `heartbeat.request`를 보내는 서버와 함께 설치해야 합니다. 이 표시는 계량기·프린터의 정상 동작을 보장하지 않습니다.

### 정상 종료와 재시작

먼저 현장의 새 계량 입력을 멈추고, **프로그램의 실행 계정으로** 로그인한 상태에서 바탕화면의 **`ScaleLedger Client 종료` 바로가기**를 누릅니다. 이 바로가기는 `pythonw.exe main.py --stop`을 실행하며 결과 창은 표시하지 않습니다. 종료 바로가기가 없거나 성공·실패 메시지를 확인하려면 같은 계정의 Windows PowerShell에서 아래 명령을 실행합니다. 설치 경로는 실제 현장 경로에 맞춥니다.

```powershell
Set-Location C:\ScaleLedger\Client
.\.venv\Scripts\python.exe main.py --stop
```

프로그램은 장비를 멈추고 대기 중인 기록 처리와 DB·통신 연결 정리를 기다립니다. 설정 파일에 오류가 있어도 종료 명령을 사용할 수 있습니다. 최대 30초 내 종료를 확인하지 못하면 실패로 끝나며 강제로 종료하지 않습니다. `python.exe`로 실행했을 때는 오류 메시지가 표시되고, 창 없는 종료 바로가기는 표시하지 않습니다. 종료되지 않았다면 담당자가 위 명령으로 결과와 로그를 확인해야 합니다.

예약 작업으로 시작했다면 작업 스케줄러의 **준비(Ready)** 상태와 최근 `sys.lifecycle.process.shutdown` 로그를 확인한 뒤 설정을 변경하거나 시작 바로가기를 누릅니다. 직접 실행했다면 해당 `main.py` 프로세스가 종료됐는지 확인합니다. 아직 실행 중일 때 시작 요청을 보내면 중복 실행 방지 때문에 무시됩니다.

PC 종료·재부팅 때 프로그램의 정상 종료를 자동 요청하는 기능은 없습니다. 작업 관리자의 프로세스 끝내기, 작업 스케줄러의 강제 종료, Windows 종료나 전원 차단 중에는 아직 저장하지 못한 계량 기록이 누락될 수 있습니다. 처리 중인 기록의 정리를 기다려야 할 때는 위 정상 종료 바로가기를 사용하고 종료 상태를 확인합니다.

## 설정과 기록 보관

프로그램은 실행한 작업 폴더와 관계없이 설치된 프로그램 폴더 아래의 파일을 사용합니다. 예시 설치 경로는 `C:\ScaleLedger\Client`이며, 설치 후 폴더를 임의로 옮기지 않습니다.

| 위치 | 내용과 관리 방법 |
| --- | --- |
| `config.toml` | 서버 주소와 로그 설정. 설치 담당자가 입력하고, 변경 후에는 프로그램을 다시 시작합니다. |
| `data/db.sqlite3` | 저장된 계량대·카드 설정과 아직 전송하지 못한 계량 기록. 임의로 삭제하거나 옮기지 않습니다. |
| `data/credential.json` | 이 PC의 장비 자격증명과 등록한 서버 주소. 관리자 승인은 이 값에 연결되므로 지우거나 손상되면 새로 만들어지고 다시 승인받아야 합니다. 다른 PC로 복사하면 그 PC도 같은 장비로 동작하므로 복사하거나 공유하지 않습니다. |
| `logs/client.log` | 현재 실행 로그. 장애 시 발생 시각과 함께 담당자에게 전달합니다. |
| `logs/client.log.1`부터 | 이전 로그. 숫자가 작을수록 최근 기록입니다. |

처음 실행하면 클라이언트 DB와 자격증명 파일을 자동으로 만듭니다. 첫 설치는 서버와 클라이언트의 새 데이터베이스를 기준으로 하며, 관리 프로그램에서 이 PC를 승인하고 생산자·품목·카드를 등록한 뒤 사용합니다.

직전 버전에서 업데이트하면 시작할 때 기존 카드 DB를 자동 갱신해 품목 없는 카드를 저장할 수 있도록 합니다. 저장된 카드·장비 설정과 미전송 계량 기록은 보존하며 DB를 삭제할 필요가 없습니다. 갱신 중 오류가 나면 카드 DB 변경을 되돌리고 시작을 중단하므로 로그를 담당자에게 전달합니다. 다른 구조의 오래된 DB는 별도 전환 절차가 필요합니다.

이 버전은 계량 기록을 해당 계량대에 연결하는 서버와 함께 적용합니다. 계량대 연결을 지원하지 않는 이전 버전에서 전환할 때는 새 계량 입력을 멈추고 서버와 클라이언트를 모두 정상 종료한 뒤, 초기화 대상으로 확정한 테스트 DB를 새로 준비하고 장비 승인·기준정보 동기화를 다시 마칩니다. 기존 미전송 기록이 남아 있으면 먼저 처리 방법을 확인하며, 서버 DB를 초기화한 뒤에는 이전 클라이언트 DB의 기록이나 장비 설정을 다시 사용하지 않습니다.

계량대는 계량을 확정할 때 기록에 함께 저장됩니다. 서버 연결이 끊기거나 클라이언트를 재시작하고 설정을 다시 받아도 미전송 기록의 계량대는 바뀌지 않습니다. 계량대 이름을 변경하면 관리 화면의 과거 기록에도 현재 이름이 표시되며, 이미 출력한 종이 전표의 이름은 그대로 남습니다.

**서버로 전송이 성공한 계량 기록은 클라이언트 DB에서 삭제됩니다.** 클라이언트 파일만으로 전체 계량 이력을 복구할 수 없으므로 관리 프로그램의 데이터 백업이 필요합니다. 백업 매체·주기·복구 방법은 설치 담당자에게 인수인계받습니다. 자동 백업 기능은 아직 제공하지 않습니다.

### 서버 주소와 로그 설정

설치 담당자가 [config.example.toml](config.example.toml)을 같은 폴더에 `config.toml` 이름으로 복사하여 현장에 맞게 수정합니다. UTF-8로 저장하고 실제 파일명이 `config.toml.txt`가 되지 않도록 확인합니다. 기존 설정이 있으면 새 예제로 덮어쓰지 않습니다.

```toml
server_url = "http://127.0.0.1:8000"

[logging]
level = "INFO"
max_bytes = 10485760
backup_count = 10
```

| 항목 | 의미 |
| --- | --- |
| `server_url` | 실제 관리 서버 주소와 포트. 같은 PC의 서버라면 위와 같은 주소를 사용하되, `8000`은 실제 서버 포트로 맞춥니다. 다른 PC의 서버라면 그 PC의 주소를 입력합니다. |
| `level` | 기록할 최소 로그 수준. `DEBUG`, `INFO`, `WARNING`, `ERROR`, `CRITICAL` 중 하나이며 일반 운영은 `INFO`입니다. |
| `max_bytes` | 파일 하나의 회전 기준 크기(바이트). 기본값 `10485760`은 10MiB입니다. |
| `backup_count` | 현재 파일을 제외한 이전 로그 파일 수. 기본값은 10개입니다. |

`[logging]`과 그 안의 항목은 생략하면 위 기본값을 사용합니다. 크기와 보관 개수는 1 이상의 정수입니다. 기본 설정은 현재 파일 1개와 이전 파일 10개를 보관하며, 오래된 로그부터 자동으로 지웁니다. 크기는 회전 기준이므로 전체 디스크 사용량의 엄격한 상한은 아닙니다. 파일 회전에는 Python 표준 핸들러를 사용합니다.

서버 접속에는 아이디·암호를 설정하지 않습니다. 프로그램이 처음 실행할 때 이 PC의 자격증명을 만들어 `data/credential.json`에 저장하고, 관리자가 승인하면 그 자격증명으로 접속하므로 TOML에 입력할 값은 없습니다. 장비 PC는 서버 하나에만 등록됩니다. `server_url`을 바꾸고 다시 시작하면 이전 서버의 계량대·카드 설정과 아직 전송하지 못한 계량 기록을 지우고, 새 자격증명으로 새 서버의 승인을 기다립니다. 같은 서버의 주소만 바뀐 경우(`localhost`↔`127.0.0.1`, IP 변경)도 같으므로 관리자가 기존 장비 PC에 다시 연결합니다. 지워진 계량 기록은 출력된 전표를 확인해 관리 프로그램에서 직접 등록할 수 있습니다. 설치 중 입력하는 Windows 계정과 암호는 작업 스케줄러 실행용이며, 이 암호가 바뀌면 작업 스케줄러에 저장된 자격 증명도 갱신해야 합니다.

## 장애 대응

장비 통신은 요청 쓰기와 응답 읽기에 각각 2초의 제한을 둡니다. 송수신 전체를 합쳐 2초로 제한하는 것은 아니며, 응답이 일찍 도착하면 즉시 다음 처리를 진행합니다. 현재 이 시간은 프로그램 기본값이며 서버나 `config.toml`에서 변경할 수 없습니다.

| 상황 | 운영자가 할 일 |
| --- | --- |
| 관리 서버 연결이 끊김 | 최초 승인과 동기화를 마친 PC는 저장된 정보로 계량·출력·로컬 저장을 계속할 수 있습니다. 연결 복구 후 미전송 기록이 관리 화면에 반영됐는지 확인합니다. |
| 계량은 되는데 실시간 화면만 갱신되지 않음 | 수신 상태와 서버·클라이언트 버전을 확인합니다. 네트워크 장애는 자동 재연결하지만 인증·입력·중복 발행·순번·과도한 송신 오류로 상태 발행을 중단한 경우에는 로그의 `net.telemetry.stopped`와 종료 코드를 확인하고 원인을 해결한 뒤 클라이언트를 정상 재시작합니다. 계량·출력·기록 업로드는 계속할 수 있습니다. |
| 처음 설치한 PC에서 서버에 연결할 수 없음 | 초기 등록과 설정을 마칠 수 없으므로 담당자에게 서버 주소·실행 상태·연결 확인을 요청합니다. |
| 장비 응답이 없거나 카드가 인식되지 않음 | 전원·케이블·카드 등록을 확인하고 담당자에게 알립니다. 재설치나 `data/` 삭제로 해결하려 하지 않습니다. |
| 장비 응답 시간 초과(`hw.serial.timeout`) | 읽기 제한 시간 안에 장비 응답을 모두 받지 못한 상태로, 프로그램이 해당 포트를 닫고 다시 연결합니다. 반복되면 장비 전원·통신 케이블과 Windows 장치 관리자의 COM 포트가 등록된 계량대 설정과 일치하는지 확인합니다. 담당자에게 발생 시각·포트와 로그의 수신 바이트 수·소요시간을 전달합니다. 출력 중 발생했다면 전표와 저장 기록을 먼저 확인합니다. 자동 재출력은 하지 않습니다. |
| 장비 요청 쓰기 시간 초과(`hw.serial.write_timeout`) | 쓰기 제한 시간 안에 요청 쓰기를 마치지 못해 해당 포트를 다시 연결합니다. 전원·케이블·COM 포트를 확인하고 발생 시각·포트와 요청 크기·소요시간을 담당자에게 전달합니다. 출력 요청의 일부 또는 전부가 장비에 전달됐을 수 있으므로 전표와 저장 기록을 먼저 확인합니다. 자동 재출력은 하지 않습니다. |
| 프린터 용지 없음 | 새 계량 입력을 멈추고 용지를 보충합니다. 담당자는 `hw.printer.status_changed` 로그의 `status=no_paper`와 이후 상태를 확인합니다. 이미 처리한 건은 저장 기록과 실물 전표를 먼저 대조합니다. 프로그램은 용지 없음만으로 계량·출력 명령을 자동 중단하거나 전표를 재출력하지 않습니다. |
| 장비 응답의 일부 값을 읽을 수 없음(`hw.protocol.field_invalid`) | 읽을 수 있는 값으로 계속 동작합니다. 중량을 읽을 수 없으면 해당 계량대만 적색등과 오류 상태로 계량을 멈추고, 음성 상태를 읽을 수 없으면 안내만 생략하며, 비정상 카드 값은 무시합니다. 프린터 상태를 읽을 수 없으면 확인 불가로 기록·전송하며 계량은 계속합니다. 온도·팬/히터 설정은 계량에 쓰지 않습니다. 계량대마다 항목별로 처음 한 번 남는 원시 응답(`raw`)을 담당자에게 전달하고, 팬·히터 설정값을 읽을 수 없으면 장비의 온도 관리 설정을 제조사에 확인합니다. |
| 카드를 새로 등록·변경했는데 반영되지 않음 | 변경 알림을 지원하는 서버에 연결돼 있으면 자동으로 다시 조회합니다. 연결 상태와 `sys.sync.settings.completed` 로그를 확인합니다. 동기화 실패 중에는 마지막 정상 정보를 사용하므로 변경한 카드의 사용을 멈추고 담당자에게 알립니다. 연결 복구나 정상 재시작 때도 다시 조회합니다. |
| 설정 오류가 로그에 표시됨 | 담당자가 `config.toml`을 수정하고 검사한 뒤 재시작합니다. 설정이 잘못되면 서버 통신은 중단되지만, 저장된 장비 정보가 있으면 로컬 계량은 계속합니다. |
| 관리 프로그램의 승인을 기다림 | 로그에 `biz.enrollment.pending`이 남습니다. 관리자가 관리 프로그램에서 이 PC를 승인합니다. 저장된 설정이 있으면 승인 전에도 계량을 계속합니다. |
| 장비 인증이 거부되거나 PC 연결이 해제됨 | 서버의 등록 상태를 담당자가 확인합니다. 마지막 장비 설정과 미전송 기록은 유지됩니다. 연결이 해제된 PC는 새 자격증명으로 다시 승인을 요청하므로(`biz.enrollment.revoked`) 관리자가 기존 장비 PC에 다시 연결합니다. |
| 자격증명을 사용할 수 없음 | 로그의 `sys.auth.credential.unusable`은 `data/credential.json`을 읽거나 쓸 수 없는 경우입니다. 서버 통신만 멈추고 계량은 계속합니다. 담당자가 `data/` 폴더 권한과 디스크 상태를 확인하고 재시작합니다. |
| 전표 출력과 완료 안내가 지연됨 | 새 계량을 멈추고 계량물을 유지합니다. 담당자는 `biz.weighing.local_save_pending`·`biz.weighing.local_save_failed` 및 `biz.record.local_save_failed` 로그에서 UUID·원인과 디스크 공간·DB 접근 상태를 확인합니다. 저장 대기만으로 미저장을 단정하거나 카드를 다시 대지 않습니다. 저장 실패 때는 적색등과 관리자 확인 음성을 내보내고 같은 계량 원본을 재시도합니다. |
| 전표는 나오지만 음성 안내가 생략됨 | 담당자는 `hw.speaker.timeout`·`hw.speaker.playback_uncertain` 로그와 장비의 음성 상태를 확인합니다. 음성 오류만으로 저장·출력을 취소하지 않으며, 재생 여부가 불확실한 동안 새 음성을 보내지 않습니다. `hw.speaker.recovered`는 해당 방송의 재생·종료를 확인하여 새 안내를 다시 허용했다는 뜻입니다. |
| 전표가 없거나 서버 기록이 누락·반려됨 | 발생 시각·계량대·카드번호·출력물을 보관하고 담당자에게 전달합니다. 완료 음성이나 전표만으로 서버 전송 성공을 판단하지 않습니다. |
| 바로가기를 눌러도 실행되지 않음 | 작업 스케줄러 상태와 최근 실행 결과를 확인합니다. 담당자가 실행 계정·암호·일괄 작업 로그온 권한·Python 설치·폴더 권한·로그를 점검합니다. 시작 요청이 성공해도 계속 준비 상태이고 로그가 없다면 일괄 작업 로그온 권한을 먼저 확인합니다. |

클라이언트는 프린터의 정상(`normal`)·용지 없음(`no_paper`)·전송 중(`transmitting`)·확인 불가(`unknown`)를 구분해 현재 상태를 보관합니다. 상태가 바뀔 때 로그를 남기며, 용지 없음·확인 불가로 바뀌면 경고 수준입니다. 정상 종료에 따른 확인 불가 전환은 경고하지 않습니다. 중량을 읽지 못해도 같은 장비 응답의 프린터 상태는 계속 확인하고, 통신이 끊기거나 다시 연결한 직후에는 새 응답을 받을 때까지 확인 불가로 처리합니다. 전송 중 자체는 고장이 아니며 정상 상태도 개별 전표의 실제 인쇄 성공을 보장하지 않습니다. 용지 잔량·소진 임박과 세부 고장 원인은 장비 사양에서 제공하지 않습니다.

프린터 상태는 같은 응답의 중량·음성·출력·온도와 공통 관측 시각·경과 시간을 사용해 서버에 전송합니다. 서버에서 용지 없음을 장비 문제로 표시하려면 새 통신 계약을 처리하는 서버 버전이 필요합니다. 현재 서버의 관리 화면에 표시되는 기능은 아직 구현되지 않았으므로 현장에서는 로그와 실제 프린터를 함께 확인합니다. 장비가 보고한 음성 번호·출력 상태는 스피커 발성이나 팬 회전의 물리적인 성공 확인을 뜻하지 않습니다.

온도는 장비가 보고한 정수값을 그대로 전달하며, 읽을 수 없으면 확인 불가로 처리합니다. 시험 장비에서 `+28`·`+29` 수신을 확인했지만 단위·센서 위치·고장 시 반환값은 미확인입니다. 따라서 섭씨나 내부 온도로 단정하거나, 이 값으로 팬·히터의 정상 여부를 판단하지 않습니다.

팬·히터 작동 온도 설정값도 같은 응답에서 읽어 함께 전달합니다. 장비가 보고한 현재 설정값이며, 읽을 수 없으면 확인 불가로 처리합니다. 실제 출력 상태와 설정값을 구분해 확인할 수 있지만, 이 보고 기능이 장비의 설정을 변경하지는 않습니다.

통신 오류나 서버 오류로 전송하지 못한 기록은 PC에 보관하며 다시 전송을 시도합니다. 내용 오류로 반려된 기록은 담당자의 확인이 필요합니다.

로컬 저장 대기 중 정상 종료를 요청하면 장비는 멈추고 이미 요청한 저장 처리가 끝날 때까지 기다립니다. 쓰기 실패가 계속되면 메모리의 계량은 종료·재부팅 후 복구되지 않습니다. `biz.weighing.stopped_before_save_confirmation`이 있거나 저장 장애 중 종료했다면, 담당자가 해당 UUID의 로컬·서버 기록과 로그를 확인한 뒤 재계량 여부를 판단합니다. 저장은 끝났어도 종료·통신 장애로 출력되지 않은 전표를 자동 재출력하지 않습니다.

생산자·품목·카드와 본인 Gateway·Station 설정은 서버 연결·재연결·변경 알림 때 함께 조회합니다. 전체 정보를 정상적으로 받은 뒤 저장하고 적용하며, 실패하면 마지막 정상 정보로 계량을 계속하면서 재시도합니다. 평상시 정기 조회는 하지 않습니다. 변경 알림을 지원하는 서버와 함께 설치해야 연결 유지 중 변경이 자동으로 반영됩니다.

Gateway·Station 이름은 설정 적용 후 생성하는 전표부터 반영됩니다. 이름이나 카드 정보만 바뀌면 장비를 재시작하지 않습니다. Station 삭제나 포트 변경은 해당 장비의 작업을 중단할 수 있으므로 새 계량 입력을 멈추고 진행 중인 계량을 마친 뒤 변경합니다. 진행 중 카드 재배정은 피하고, 변경 후 다음 계량의 전표를 확인합니다.

## 로그 확인

현재 기록은 프로그램 폴더의 `logs/client.log`, 이전 기록은 `client.log.1`부터 확인합니다. 담당자에게 전달할 때는 발생 시각과 해당 시각이 포함된 로그 파일을 함께 제공합니다. 실행 계정에 로그 폴더 쓰기 권한이 없는 경우 로그 자체가 생성되지 않을 수 있으므로 작업 스케줄러의 실행 결과도 확인합니다.

예상 가능한 시리얼 연결 실패·쓰기 시간 초과·응답 시간 초과는 긴 traceback 없이 원인을 기록합니다. 대기 중에는 WARNING, 카드 확인·계량·저장·출력 중에는 카드번호와 계량 이벤트 정보를 포함한 ERROR로 남깁니다. 예상하지 못한 프로그램 오류에는 분석용 traceback을 유지합니다.

정상 응답을 받았어도 한 번의 통신에 1초 이상 걸리면 `hw.serial.slow_exchange` 경고를 포트별로 최대 10분에 한 번 남깁니다. 요청 종류·크기와 쓰기·읽기 소요시간으로 어느 구간이 느린지 확인할 수 있습니다. 이 시간은 `write()`·`read()` 호출에 걸린 시간으로 장비 처리와 OS·USB 버퍼의 영향을 포함하며, 순수 선로 전송 시간이나 실제 종이 출력 완료 시간을 뜻하지 않습니다.

응답하지 않는 장비나 서버 연결·설정 동기화에서 반복되는 일부 오류는 처음 상세 기록한 뒤 횟수를 모아 요약합니다. 10분 이상 지난 뒤에도 같은 종류의 오류가 다시 발생하면 생략한 반복 횟수, 해당 장애의 누적 횟수, 경과 시간과 최근 오류를 남깁니다. 장비별로 집계하며 서버 통신 집계는 별도로 유지합니다. 오류 종류별 횟수 통계는 제공하지 않습니다.

장비는 마지막 실패 이후 30초 이상 지난 정상 통신에서, 서버는 필요한 설정 동기화가 성공했을 때 복구를 기록합니다. 복구나 프로그램 재시작 후에는 집계를 새로 시작합니다. 반복 로그의 개별 발생 시각과 상세 내용은 생략되므로 요약 횟수도 함께 확인합니다. 모든 오류가 요약되는 것은 아니며, 개별 계량 처리의 주요 오류·기록 업로드·heartbeat·로컬 저장 오류 등은 별도로 기록합니다. 요약은 WARNING, 복구는 INFO 수준이므로 일반 운영에서는 INFO 설정을 유지합니다.

## 설치 담당자 절차

### 1. PC와 Python 준비

1. 소스를 로컬 고정 디스크의 경로에 배치합니다. 이하 예시는 `C:\ScaleLedger\Client`입니다. 네트워크 공유·매핑 드라이브·이동식 드라이브에 설치하지 않습니다.
2. Python 3.14, uv, 시리얼 장비 드라이버를 준비합니다. 기본 Python과 가상환경 모두 실행 계정이 읽고 실행할 수 있어야 합니다. 설치 개발자의 개인 AppData 아래 Python으로 만든 가상환경은 다른 실행 계정에서 동작하지 않을 수 있습니다.
3. 암호가 있는 Windows 표준 사용자 계정을 실행 계정으로 정합니다. 바탕화면 시작과 정상 종료도 이 계정으로 사용합니다. Windows 암호가 필요하며 Hello PIN으로 대체하지 않습니다. 관리자가 `secpol.msc`의 **로컬 정책 → 사용자 권한 할당 → 일괄 작업으로 로그온**에 실행 계정을 추가하고, **일괄 작업으로 로그온 거부**에는 계정이나 소속 그룹이 포함되지 않았는지 확인합니다. 조직 정책으로 관리하는 PC는 담당 관리자가 설정합니다. 설치 스크립트는 이 권한을 자동 부여하지 않으며, 권한이 없으면 작업 등록과 시작 요청이 성공해도 실제 프로그램이 실행되지 않을 수 있습니다.
4. 운영 중 절전하지 않도록 전원 정책을 설정하고 관리 서버의 부팅 자동 실행도 준비합니다. 설치 스크립트는 Windows 계정 생성이나 전원 정책 설정을 수행하지 않습니다.
5. 프로그램 폴더에서 잠금 파일에 지정된 의존성을 설치합니다. 아래 Python 경로는 실제 설치 위치로 바꿉니다.

```powershell
Set-Location C:\ScaleLedger\Client
uv sync --frozen --no-dev --python 'C:\Program Files\Python314\python.exe'
```

오프라인 현장은 반입 전에 해당 Windows·Python 버전에 맞는 Python 설치 파일, uv, 드라이버와 의존성 캐시를 준비합니다. 현장에서 아래 명령의 성공을 확인합니다. 다른 운영체제에서 만든 `.venv`를 복사하지 않습니다.

```powershell
uv sync --offline --frozen --no-dev --python 'C:\Program Files\Python314\python.exe'
```

### 2. 설정 입력과 검사

위 [서버 주소와 로그 설정](#서버-주소와-로그-설정)에 따라 `config.toml`을 작성합니다. 관리 서버의 허용 호스트와 방화벽도 실제 접속 주소에 맞춥니다.

```powershell
.\.venv\Scripts\python.exe main.py --check-config
```

종료 코드 0은 유효한 설정, 2는 설정 오류입니다. 이 검사는 DB를 만들거나 서버·장비에 연결하지 않습니다. 서버 접속·등록·실제 장비 동작은 첫 실행에서 별도로 확인합니다.

### 3. 자동 실행과 바로가기 등록

**수동 등록과 설치 스크립트 중 하나를 선택합니다.** 스크립트 사용은 필수가 아니며, Python·의존성·실행 계정·TOML 설정은 어느 방식이든 앞 단계에서 준비합니다. 부팅 작업에는 시작 명령만 등록합니다. 종료 바로가기는 필요할 때 직접 사용하며, PC 종료·재부팅 때 자동 호출되지는 않습니다.

#### 수동 등록

관리자 권한으로 작업 스케줄러의 **작업 만들기**를 열고 아래 값을 설정합니다. 경로는 실제 설치 위치로 바꿉니다.

| 항목 | 설정 |
| --- | --- |
| 이름 | `ScaleLedger Client` |
| 보안 옵션 | 앞서 정한 표준 실행 계정, **사용자의 로그온 여부에 관계없이 실행**, 가장 높은 수준의 권한 사용 안 함 |
| 암호 | 작업 저장 시 실행 계정의 Windows 암호 입력. **암호를 저장하지 않음**은 선택하지 않음 |
| 트리거 | **시작할 때**(PC 부팅), 사용 |
| 동작: 프로그램/스크립트 | `C:\ScaleLedger\Client\.venv\Scripts\pythonw.exe` |
| 동작: 인수 추가 | `"C:\ScaleLedger\Client\main.py"` |
| 동작: 시작 위치 | `C:\ScaleLedger\Client` |
| 조건 | 유휴·네트워크·AC 전원 조건 해제, 배터리 전환 시 중지 해제 |
| 설정 | 요청 시 실행 허용, 실행 시간 제한 해제, 이미 실행 중이면 **새 인스턴스 시작 안 함** |

관리자가 프로그램 폴더의 보안 속성에서 실행 계정에 소스·기본 Python·가상환경의 읽기·실행 권한을 확인합니다. 프로그램 폴더 아래 `data`와 `logs` 폴더를 만들고 실행 계정에 두 폴더의 수정 권한을 부여합니다.

실행 계정으로 로그인해 바탕화면에 다음 두 바로가기를 만듭니다. 둘 다 **시작 위치**는 `C:\ScaleLedger\Client`로 지정하고 관리자 권한으로 실행하지 않습니다.

| 바로가기 이름 | 대상 |
| --- | --- |
| `ScaleLedger Client 시작` | `"C:\ScaleLedger\Client\.venv\Scripts\pythonw.exe" "C:\ScaleLedger\Client\main.py"` |
| `ScaleLedger Client 종료` | `"C:\ScaleLedger\Client\.venv\Scripts\pythonw.exe" "C:\ScaleLedger\Client\main.py" --stop` |

이 시작 바로가기는 프로그램을 직접 실행하므로 작업 스케줄러 상태에 반영되지 않습니다. 예약 작업을 시작하는 바로가기를 원하면 대상에 `schtasks.exe /run /tn "ScaleLedger Client"`를 지정하고 실행 계정으로 해당 작업의 읽기·실행 권한을 확인합니다. 아래 스크립트는 이 권한도 함께 설정합니다.

#### 스크립트로 등록

수동 등록 대신 자동 등록하려면 **관리자 Windows PowerShell 5.1 이상**에서 [설치 스크립트](scripts/install-windows.ps1)를 실행합니다.

```powershell
Set-Location C:\ScaleLedger\Client
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\scripts\install-windows.ps1
```

이 명령의 실행 정책 지정은 해당 PowerShell 프로세스에만 적용됩니다. 조직 정책으로 스크립트 실행이 제한된다면 담당 정책에 맞춰 실행합니다.

스크립트는 설정과 가상환경을 검사한 뒤 실행 계정과 Windows 암호를 입력받아 다음 구성을 등록합니다.

| 항목 | 설정 |
| --- | --- |
| 예약 작업 | `ScaleLedger Client`, PC 부팅 시 로그인 여부와 무관하게 실행 |
| 실행 명령 | 프로그램 폴더의 `.venv\Scripts\pythonw.exe`로 `main.py` 직접 실행 |
| 계정 권한 | 일반 권한으로 실행. 실행 계정에 프로그램 읽기·실행, `data/`·`logs/` 수정, 예약 작업 읽기·실행 권한 부여 |
| 실행 조건 | 시간 제한 없음, 네트워크·유휴 상태 조건 없음, 배터리 전환 시 중단하지 않음 |
| 중복과 재시도 | 실행 중 추가 시작 무시, 예약 작업 실패 재시도는 1분 간격 최대 3회로 설정. 프로세스 비정상 종료의 자동 복구는 보장하지 않음 |
| 시작 바로가기 | 공용 바탕화면의 `ScaleLedger Client 시작`으로 같은 예약 작업 실행 |
| 종료 바로가기 | 공용 바탕화면의 `ScaleLedger Client 종료`로 `pythonw.exe main.py --stop` 실행. 프로그램과 같은 실행 계정으로 사용 |

암호는 예약 작업 등록을 위해 Windows에 전달하며 TOML이나 로그에 쓰지 않습니다. 네트워크 접근 제약이 있는 **암호를 저장하지 않는 S4U 옵션**은 사용하지 않습니다.

스크립트는 신규 설치용입니다. 같은 이름의 작업이나 시작·종료 바로가기 중 하나라도 있으면 덮어쓰지 않고 중단합니다. 이미 수동 등록했다면 스크립트를 다시 실행할 필요가 없습니다. 중간 실패 시 만들어진 폴더·권한·작업·바로가기가 남을 수 있으므로 결과 메시지에 따라 확인합니다. 등록 직후 프로그램이 자동으로 시작되지는 않습니다.

운영 계정으로 로그인해 바탕화면 바로가기로 첫 실행하고, 관리 프로그램에서 승인을 기다리는 이 PC를 승인한 뒤 Station·카드 설정을 마칩니다. 관리자 계정에서 설정 검사에 성공했어도 실제 실행 계정의 기본 Python 접근 권한·장비 연결은 별도로 확인해야 합니다.

### 4. 점검용 명령

스크립트가 만든 시작 바로가기와 다음 시작 명령은 같은 작업을 실행합니다. 수동으로 만든 직접 실행 바로가기는 해당하지 않습니다. 시작 명령 성공은 요청 접수이며, 실제 상태와 로그·계량 결과를 확인해야 합니다.

```powershell
schtasks.exe /run /tn "ScaleLedger Client"
Get-ScheduledTask -TaskName 'ScaleLedger Client' | Select-Object TaskName, State
Get-ScheduledTaskInfo -TaskName 'ScaleLedger Client' |
    Select-Object LastRunTime, LastTaskResult
```

종료와 재시작은 위 [정상 종료와 재시작](#정상-종료와-재시작)을 따릅니다. 정상 종료 코드는 0이므로 실패 재시작 대상이 아닙니다. 콘솔로 직접 점검할 때는 예약 작업이 종료된 상태에서 `.\.venv\Scripts\python.exe main.py`를 실행하고 `Ctrl+C`로 정상 종료할 수 있습니다.

Windows 가상환경에서 아래 테스트를 실행하면 Windows 이벤트의 프로세스 간 전달 테스트까지 수행합니다. 로그인 전 작업과 바탕화면 세션 사이의 시작·종료는 실제 부팅 인수 검증으로 확인합니다.

```powershell
.\.venv\Scripts\python.exe -W error -m unittest discover -v
```

## 현장 인수와 제한사항

설치 담당자와 운영자가 다음 항목을 함께 확인합니다.

- 첫 등록 후 실제 계량대·카드 정보, 전표, 관리 화면의 기록을 대조합니다.
- PC를 재부팅하고 로그인하지 않은 상태에서 프로그램과 장비가 동작하는지 확인합니다.
- 운영 계정의 바로가기 시작·정상 종료·재시작을 확인합니다. 반복 클릭해도 프로그램이 하나만 실행돼야 합니다.
- 테스트 기록만 사용하는 상황에서 비정상 종료 후 상태 확인·수동 재시작, 서버 중단 중 계량, 서버 복구 후 미전송 기록 반영을 확인합니다.
- PC 시각·시간대, 장비 단위·정밀도, 실제 COM 포트·드라이버·프린터 출력과 장시간 운전을 확인합니다.
- 관리 화면 주소, 설치 경로·실행 계정, 카드 변경 반영 방법, 백업·복구 절차, 장애 연락 담당자를 인수인계합니다.

현재 알아야 할 제한사항은 다음과 같습니다.

- Parallels Windows 11 ARM64와 CPython 3.14 x64 환경에서 기존 설치·실행 계정 권한·부팅 작업·중복 실행 차단·정상 종료와 테스트 96개를 검증했습니다. 이후 추가한 종료 바로가기와 종료 요청 경합 보완은 Windows에서 아직 재검증하지 않았습니다. 사용자 로그인보다 먼저 프로세스가 시작된 것을 확인했으나, 로그인하지 않은 상태로 계속 운전하는 조건과 운영 계정의 실제 바탕화면 클릭·세션 간 종료는 현장에서 추가 확인해야 합니다.
- 예약 작업의 실패 재시도 설정이 있어도, 이 Windows 환경에서는 실행 중 강제 종료와 종료 코드 1 이후 자동 재시작이 일어나지 않았습니다. 무인 자동 복구가 필요하면 별도의 실행 관리 구성을 마련해야 합니다.
- 서버 장애 중 기동·계속 운전과 복구 후 재전송은 모의 장비와 로컬 통신으로 검증했습니다. 실장비·드라이버·실물 출력과 장시간 운전은 남아 있습니다.
- 중량은 정수 kg로 기록하고 안정 상태가 아니어도 카드를 댄 순간 받은 값으로 확정합니다. 실제 장비의 단위·표시 형식과 맞는지 확인해야 합니다.
- 로컬 저장 확인 전에는 출력·완료 안내를 하지 않습니다. 용지 없음·출력 결과 불명 처리는 아직 보강이 필요합니다. 음성은 계량·출력을 기다리게 하지 않으며 시작·종료를 15초 안에 확인하지 못하면 경고 로그만 남깁니다. 계량 기록을 다시 생성하지 않으며, 출력 중 오류가 나면 자동 재출력하지 않습니다. 음성 재생 시간과 음성 재생 중 출력은 시험 장비 한 대에서 확인했으며, 현장 장비·실제 차량 흐름·전원 차단 조건과 신호등 동작의 인수 검증은 남아 있습니다.
- 서버에서 변경하는 전표 양식, 전표 재발행과 자동 백업은 아직 제공하지 않습니다.
